# 9차시. 휴대폰에서 보기 좋게 다듬기

⏱ 25분 (개념 6 · 실습 15 · 정리 4) · 결과물: **모바일 여행 지도**

## 학습 목표
- 모바일 우선 반응형(데스크톱=사이드 패널, 모바일=바텀시트) 구조를 이해한다.
- 현재 위치 버튼의 동작과 **개인정보 원칙**을 설명한다.
- `app/theme.css`·`config/site.ts` 로 브랜딩을 바꾼다.

## 선수 준비사항
- 6~7차시 결과. 코드: `components/AtlasApp.tsx`, `components/layout/SiteHeader.tsx`, `components/layout/MobileBottomSheet.tsx`, `lib/hooks.ts`, `app/theme.css`, `config/site.ts`
- 크롬 개발자 도구의 **기기 모드**(F12 → Ctrl+Shift+M) 또는 실제 휴대폰(같은 와이파이의 `http://<PC IP>:3000`).

## 강사 설명 핵심 개념
1. **모바일 우선**: 지도가 화면의 주인공, 목록은 **바텀시트**(접기/절반/전체). 데스크톱은 왼쪽 패널 + 오른쪽 지도.
2. **터치 대상**: 버튼 최소 약 44px. 칩·시트 핸들·지도 버튼을 크게.
3. **스크롤 충돌 방지**: 시트 안만 스크롤(`overscroll-behavior: contain`), 지도는 지도대로 제스처.
4. **현재 위치**: 접속 즉시 요청하지 않고 **버튼을 눌렀을 때만** 브라우저에 요청. 좌표는 **서버로 보내지 않고 저장하지 않음**. 거부·실패 시 안내 문구.
5. **브랜딩**: 이름·지역은 `config/site.ts`, 색·글꼴은 `app/theme.css` 한 곳에서.

## 단계별 실습
1. 기기 모드(예: 360×800)로 전환 → 하단 시트와 상단 테마 칩 확인.
2. 시트 상단 손잡이를 **손가락으로 끌어** 높이를 바꿔 본다(놓으면 접힘/절반/전체 중 가까운 단계로 붙음). 탭하면 단계가 순환하고, 지도 위 **목록 보기/지도 보기** 버튼으로도 전환된다. 시트가 올라와도 지도의 © 출처 표시와 내 위치 버튼은 시트 위로 따라 올라온다.
3. **내 위치(◎)** 버튼 → 브라우저 권한 팝업 → 허용 시 파란 점, 거부 시 안내 확인(접속만으로는 팝업이 뜨지 않아야 함).
4. 브랜딩: `config/site.ts` 의 `brand.name`/`region.nameKo`, `app/theme.css` 의 `--color-accent` 를 내 색으로.
5. 가로 스크롤이 생기지 않는지, 글자가 잘리지 않는지 확인.

## 예상 결과물
휴대폰에서 지도·시트·칩·내 위치가 자연스럽게 동작하는 화면.

## 정상 작동 확인 방법
- 모바일 폭에서 `bottom-sheet` 가 보이고 데스크톱에서는 `side-panel`.
- 위치 거부 시 "위치 권한이 거부되었습니다…" 안내, 지도는 계속 동작.
- `npm run test:e2e -- --project=mobile` 통과.

## 초보자가 겪을 수 있는 오류 → 해결
| 증상 | 해결 |
|---|---|
| 위치 버튼이 반응 없음 | `https` 또는 `localhost` 에서만 동작. 휴대폰 접속 주소가 `http://192.168…` 이면 브라우저가 거부할 수 있음 → 배포(https) 후 확인 |
| 권한을 한 번 거부해 다시 안 물어봄 | 주소창 🔒 → 사이트 설정에서 위치 허용 |
| 마커가 시트에 가려짐 | 시트를 접거나 **전체 보기(⤢)** |
| 글자가 배경과 안 보임 | 색 대비 확인(밝은 배경엔 어두운 글자) |
| 모바일에서 페이지 자체가 흔들림 | 가로 오버플로우 요소 확인(`scrollWidth`) |
