# 10차시. 외국인 방문객용 다국어 화면

⏱ 25분 (개념 6 · 실습 15 · 정리 4) · 결과물: **다국어(한/영) 여행 지도**

## 학습 목표
- 화면 문구(UI)와 장소 콘텐츠(데이터)의 번역이 **두 곳**에 나뉨을 이해한다.
- AI 번역을 쓰되 **사람이 검토**하는 절차를 지킨다.
- 영어가 비었을 때의 폴백(한국어 대체) 정책을 확인한다.

## 선수 준비사항
- 코드: `lib/i18n/ko.ts`, `lib/i18n/en.ts`, `lib/i18n/index.ts`, `components/common/I18nProvider.tsx`, `data/places.csv`(`nameEn`, `descriptionEn`), `data/routes.json`

## 강사 설명 핵심 개념
1. **UI 문구 = 사전 파일**: `ko.ts`(기준)·`en.ts`. 키가 다르면 **TypeScript 오류**로 알려 준다(`Record<MessageKey,string>`).
2. **콘텐츠 = 데이터 열**: 장소는 `nameEn/descriptionEn`, 코스는 `titleEn/descriptionEn`.
3. **폴백 정책**: 영어가 비어 있으면 한국어로 표시 + "영어 번역이 없어 한국어로 표시됩니다" 안내. 키가 아예 없으면 한국어 → 키 이름 순.
4. **언어 유지**: 선택은 브라우저 `localStorage` 에 저장 → 새로고침해도 유지. `<html lang>` 도 갱신.
5. **AI 번역 주의**: 지명·상호명·고유명사는 틀리기 쉽다 → *원문 병기 · 공식 영문 표기 확인 · 사람 검토* 후 반영. 번역 도구에 개인정보를 넣지 않는다.

## 단계별 실습
1. 화면 오른쪽 위 **EN** 으로 전환 → 메뉴·버튼·장소명·코스 설명이 영어로 바뀌는지, 새로고침 후 유지되는지 확인.
2. `places.csv` 에서 `nameEn`/`descriptionEn` 을 비워 보고 → 영어 화면에서 한국어로 표시 + 안내 확인. (`npm run validate:data` 는 경고로 알려 줌)
3. AI로 영어 초안을 만들고, 아래 **검토 체크리스트**로 고친 뒤 CSV에 반영.
4. `en.ts` 에 새 문구가 필요하면 `ko.ts` 와 **같은 키**를 추가.
5. (도전) 일본어 추가를 설계해 본다: 어떤 파일/열이 필요한지 목록만 작성.

**번역 검토 체크리스트**
- [ ] 지명·상호명은 공식 표기/간판 표기와 일치(필요하면 `Name (한글)` 병기)
- [ ] 영업시간·주소·숫자·단위가 원문과 같은가
- [ ] 과장·거짓 표현이 늘지 않았는가
- [ ] 문장이 방문객에게 자연스러운가(원어민/동료 검토 권장)

## 예상 결과물
KO/EN 전환이 되는 지도, 영어 번역이 검토된 장소·코스 데이터.

## 정상 작동 확인 방법
- EN 전환 후 새로고침해도 EN 유지, `<html lang="en">`.
- 영어 비어 있는 장소: 한국어 + 안내.
- `npm test` 의 i18n 테스트(키 일치·폴백) 통과, `npm run test:e2e -- -g "다국어"`.

## 초보자가 겪을 수 있는 오류 → 해결
| 증상 | 해결 |
|---|---|
| `Property '"x"' is missing in type … en` 타입 오류 | `ko.ts` 에 추가한 키를 `en.ts` 에도 추가 |
| EN 에서도 한글 장소명 | CSV `nameEn` 이 비어 있음(폴백) → 번역 입력 |
| 영어 설명에 쉼표로 열이 밀림 | 값을 큰따옴표로 감싸기 |
| 번역된 상호명이 간판과 다름 | 공식 표기 확인 후 수정 |
| 언어가 새로고침하면 초기화 | 시크릿 모드/저장소 차단 → 기본 언어로 동작(정상), 일반 창에서 확인 |

## 학습 정리
UI는 사전, 콘텐츠는 데이터. 폴백으로 빈칸을 안전하게, AI 번역은 사람이 검토.
