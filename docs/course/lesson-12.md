# 12차시. 조회 통계로 인기 코스 찾고 지도 키우기

⏱ 25분 (개념 8 · 실습 12 · 정리 5) · 결과물: **운영 점검표**

## 학습 목표
- 기본 방문 통계(페이지 조회)로 **알 수 있는 것과 없는 것**을 구분한다.
- 코스별 인기도 분석에 필요한 조건을 설명한다.
- 장소를 수정하고 재배포하는 운영 사이클을 실행한다.

## 선수 준비사항
- 11차시 배포 완료. 코드: `app/layout.tsx`(Analytics 스위치), `docs/OPERATIONS.md`

## 강사 설명 핵심 개념
1. **운영 = 고치고, 확인하고, 다시 올리는 반복**: CSV 수정 → `validate:data` → push → 자동 재배포.
2. **기본 통계는 페이지 조회**: Vercel Web Analytics 는 방문자·페이지 조회·유입 경로. 켜려면 Vercel 에서 Analytics Enable + `NEXT_PUBLIC_ENABLE_ANALYTICS=true` 후 재배포.
3. **⚠️ 페이지 조회 ≠ 코스 인기도.** 이 서비스는 한 페이지(`/`)에서 코스를 바꾼다. "코스 A 가 더 인기" 를 말하려면 *코스 선택/공유 이벤트를 수집·집계*해야 한다. 이 프로젝트에는 구현되어 있지 않으며(선택 확장), 커스텀 이벤트는 플랜에 따라 제한될 수 있다.
4. **조건 체크**: ① 무엇을 "인기"로 정의? (선택 수/체류/공유) ② 이벤트 수집 수단 ③ 표본 크기 ④ 개인정보(수집 최소화) ⑤ 기간 비교.
5. **숫자를 지어내지 않는다**: 대시보드를 직접 확인하지 않은 수치는 쓰지 않는다. 방문자가 적으면 "아직 판단하기 이르다" 가 정답.

## 단계별 실습
1. 통계 켜기(선택): Vercel → Analytics → Enable, 환경변수 `NEXT_PUBLIC_ENABLE_ANALYTICS=true`, Redeploy. 켜기 어려우면 **강사 화면 시연**으로 대체.
2. 대시보드에서 **직접 확인한** 방문 수·유입을 적는다(없으면 "데이터 없음").
3. 질문 연습: "이 수치로 코스별 인기를 말할 수 있나?" → 그 이유를 한 줄로 쓴다.
4. 장소 수정 사이클: `places.csv` 에 새 장소 1곳 추가(또는 폐업 장소 수정) → `npm run validate:data` → `git push` → Vercel **Ready** → 공개 주소에서 확인.
5. **운영 점검표**(`docs/OPERATIONS.md` §9)를 내 서비스 일정에 맞게 복사해 채운다.

## 예상 결과물
- 재배포된 업데이트 1건(장소 추가/수정).
- 내 서비스의 운영 점검표(주기·담당·완료 체크).

## 정상 작동 확인 방법
- 수정한 장소가 공개 주소에 보인다.
- 대시보드 수치는 **직접 본 것만** 기록되어 있다.
- 점검표에 라이선스·API 사용량·QR 도메인 항목이 있다.

## 초보자가 겪을 수 있는 오류 → 해결
| 증상 | 해결 |
|---|---|
| 통계가 0 | 켠 직후/트래픽 없음/광고 차단기. 활성화·환경변수·재배포 확인 |
| 코스별 숫자가 안 나옴 | 정상(기본 통계는 코스를 구분하지 않음). 이벤트 수집이 별도로 필요 |
| 수정했는데 반영 안 됨 | push 했는지, Deployments 가 Ready 인지 |
| 배포 실패 | 로그의 `places.csv ○행` 확인 |

## 학습 정리
운영은 반복 사이클. 기본 통계의 한계를 알고, 근거 없는 인기 순위를 만들지 않는다.
