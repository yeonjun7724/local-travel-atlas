# 7차시. 나만의 추천 코스 3종 만들기

⏱ 25분 (개념 6 · 실습 15 · 정리 4) · 결과물: **추천 코스 3종 시각화**

## 학습 목표
- 코스 = **장소 id 의 순서 있는 목록**임을 이해한다.
- `data/routes.json` 을 작성하고 검증한다.
- 지도 위 번호 마커와 연결선이 "직선"임을 정확히 안내한다.

## 선수 준비사항
- 3차시 장소 30곳. 코드: `data/routes.json`, `components/routes/RouteExplorer.tsx`, `components/map/MapView.tsx`, `lib/data/geojson.ts`

## 강사 설명 핵심 개념
1. **코스 데이터**: `routeId, titleKo/En, descriptionKo/En, theme, placeIds[], transportMode`. **placeIds 의 순서가 방문 순서**.
2. **참조 무결성**: placeIds 는 CSV에 있는 id 여야 한다(없으면 `validate:data` 가 알려 줌). 한 코스에 같은 장소를 두 번 넣을 수 없다.
3. **좋은 코스**: 5~8곳, 걷기 편한 이동 거리, 시작→중간→마무리(식사/휴식) 흐름, 영업시간 고려.
4. **직선 연결선의 정직성**: 지도의 점선은 *장소를 순서대로 직선으로 이은 것*일 뿐 도로 경로·이동시간이 아니다. 화면에 안내문이 항상 표시된다(`route.straightNotice`).
5. 코스를 고르면 해당 장소만 번호 마커로 강조하고 지도 범위를 코스에 맞춘다.

## 단계별 실습
1. `data/routes.json` 을 열어 샘플 코스 1개의 구조를 읽는다.
2. 내 코스 3개 작성: 지도에서 순서대로 따라 걸어 보며 `placeIds` 를 정한다.
3. `npm run validate:data` — `코스가 참조하는 장소 id 가 없습니다` 가 나오면 id 철자 확인.
4. `npm run dev` → **추천 코스** 탭 → 코스 선택 → 1,2,3… 번호와 점선, 방문 순서 목록 확인.
5. 코스 상세의 안내문("직선 연결선입니다 …")을 읽고, 방문객이 오해하지 않을 문구인지 토론.

```json
{
  "routeId": "my-cafe-walk",
  "titleKo": "나의 카페 산책", "titleEn": "My Café Walk",
  "descriptionKo": "…", "descriptionEn": "…",
  "theme": "cafe-alley",
  "placeIds": ["cafe-a", "food-b", "landmark-c", "cafe-d", "nature-e"],
  "transportMode": "walking"
}
```

## 예상 결과물
코스 3종: 번호 마커 + 점선 + 방문 순서 목록 + 코스 공유 버튼.

## 정상 작동 확인 방법
- 코스 선택 시 마커가 코스 장소만 번호(1~N)로 표시.
- 지도 `data-route-line="straight"`(개발자 도구 확인) + 점선.
- `npm run test:e2e -- -g "코스"` 통과.

## 초보자가 겪을 수 있는 오류 → 해결
| 증상 | 해결 |
|---|---|
| `routes.json JSON 문법 오류` | 마지막 항목 뒤 쉼표, 따옴표 누락 확인 |
| `코스가 참조하는 장소 id 가 없습니다: …` | CSV 의 id 와 정확히 일치시키기(소문자·하이픈) |
| `같은 장소가 코스에 중복` | 한 장소는 코스에 한 번만 |
| 선이 도로를 따라가지 않는다 | **정상**(직선). 도로 경로는 8차시 선택 기능 |
| 코스를 눌러도 일부 마커가 없음 | placeIds 에 잘못된 id → validate |

## 학습 정리
코스 = 순서 있는 id 목록. 직선 연결선 ≠ 실제 경로. (완성본은 8차시에서 OSMnx 로 계산한 실제 도보 경로를 그리며, 경로 파일이 없는 코스는 이 직선 연결선으로 자동 표시됩니다.)
